# 2026 국방 AI 경진대회 2차 멘토링 요약

대상은 영상 표지에 **2026년 11월 4일**로 표시된 2차 멘토링 녹화본이며, 전체 길이는 **1시간 12분 58초**입니다. 아래 시간은 녹화 영상 안의 재생 위치입니다.

이 영상은 UGV가 자연어 명령을 해석하고, 표적·객체를 인식하고, 상대 UGV와 교전하고, 거점에 진입한 뒤 위험도를 보고하는 **여섯 임무의 통합 수행**을 설명합니다. 경기 운영 서버와의 통신, 자율주행, 인식, 전술 판단을 연결하는 구조가 핵심입니다.

## 핵심만 보기

- 3 대 3으로 경기하며 각 팀은 여섯 번 출전합니다. 본 경기는 최대 5분, 종료 뒤 M6 보고는 30초입니다.
- 경기 프로그램과 외부 LLM API 호출은 UGV에서 실행합니다. 개인 서버의 자체 AI 모델 API 허용 여부는 별도 검토 대상으로 남았습니다.
- 탄약 8발은 지정표적과 UGV 교전에서 함께 사용합니다. M4는 피격 감점 방식이며 공격자에게 별도 명중 가점을 주지 않는다고 답변합니다.
- M3는 섹터별 객체 종류·수량 집계로 평가하고, M6는 운영 서버가 집계한 실제 위험도 순위를 맞히는 과제입니다.
- 미션별 상세 배점은 OT 공개 예정입니다. P2P 통신, 개인 모델 API, 개발용 인터넷 등은 답변의 확정 수준을 구분해서 확인해야 합니다.

## 경기 운영과 실행 환경

- **3 대 3, 한 경기 총 6팀**이 동시에 참가합니다. 본선 전체는 10팀·10경기이고, 각 팀은 6회 출전합니다. BLUE·RED 진영에 각각 3회 참가하며, 모든 상대팀과 2회씩 맞붙도록 대진을 구성합니다. 연속 출전과 연속 대기는 각각 최대 2경기라는 조건을 설명합니다. 발표 화면의 대진표는 예시입니다. 대진 선택 우선순위를 정하는 서브게임과 첫날 안내를 예고합니다. **[08:26–10:45]**
- 관제 서버가 임무 지시, 시작·정지 신호, 정찰 영상, 임무 결과 수집과 실시간 채점을 담당합니다. 참가자가 정찰 드론을 직접 조종하는 방식이 아니라, **고정형 정찰 드론에서 얻은 영상을 관제 서버에 요청해 활용**하는 구성입니다. **[11:03–12:41]**
- 경기에는 임무용 노트북 한 대를 지정합니다. 노트북은 UGV 접근·프로그램 실행·디버깅 용도이며, **임무 수행 프로그램의 실행 주체는 UGV**라고 설명합니다. LLM API 접근도 UGV에서 수행하는 구조로 안내합니다. **[12:41–13:35]**
- 경기 전에는 참가팀의 통신·배터리·센서 점검과 운영팀의 객체·표적·거점 배치 및 서버 초기화가 필요합니다. **[14:01–14:47]**

## 경기 시간과 임무 관계

- 본 경기 시간은 **최대 5분**입니다. 서버가 여섯 팀에 시작 신호를 보내며, 각 팀에는 자연어 전술 명령이 주어집니다. **[14:47–15:41]**
- **M1~M4를 고정 순서대로만 수행하는 것은 아닙니다.** 위치와 전술에 따라 객체 인식, 지정표적 타격, 상대 UGV 교전을 순차 또는 병행 수행할 수 있다고 설명합니다. 다만 M1에서 해석한 지정표적 정보가 M2의 목표와 연결됩니다. **[05:37–06:31, 15:41–16:34]**
- **4분 시점에 M5의 목표거점 전술명령을 추가로 부여**합니다. 예를 들어 4분 40초에 어느 팀이 상대 진영의 지정 거점에 먼저 도착하면 그때 경기가 종료되고, 서버 명령에 따라 여섯 UGV가 모두 정지합니다. 그 시점부터 **30초 이내에 M6 결과를 보고**합니다. 설명자는 본 경기 최대 5분에 보고 30초를 더해 약 5분 30초까지를 안내합니다. **[16:47–17:47]**
- M5 목표는 **연합팀(진영) 공통 명령**이며, 가장 먼저 해당 목표거점에 도달하는 팀에 점수를 부여한다고 설명합니다. 자기 진영 거점에 잘못 진입하는 것도 판정 대상이므로 상대 진영의 올바른 목표를 구별해야 합니다. **[24:35–25:11]**

## 여섯 가지 임무

| 임무 | 수행 내용 | 준비·판정에서 볼 점 |
|---|---|---|
| M1 전술명령 해석 | 자연어 전술명령에서 지정표적, 탐색구간, 작전거점 등의 정보를 추출해 지정 형식으로 보고 | 추출한 정보와 후속 행동의 연결 |
| M2 지정표적 타격 | 지정된 감시초소·레이더시설·통신시설 등을 찾아 식별·조준하고 레이저로 타격 | 수광부에 2초 이상 연속 감지되어야 유효타격 |
| M3 전장객체 인식 | 상대 진영의 세 섹터와 공통구역을 탐색하고 객체의 종류·수량을 섹터별로 보고 | 객체 인식과 섹터 귀속·수량 집계의 결합 |
| M4 상대 UGV 타격 | 상대 UGV를 탐지·추적·조준하여 레이저로 모의 타격 | 제한 탄약과 피격에 따른 기능 제한 고려 |
| M5 목표거점 진입 | 경기 종료 1분 전에 주어지는 목표거점 정보를 바탕으로 자율 이동·진입 | 진입에 따른 경기 종료 및 전체 정지 조건 |
| M6 전장 위험도 분석 | 경기 중 관측한 정보로 상대 UGV들의 위험도를 추정하고 순위를 JSON으로 보고 | 실제 상대 상태는 비공개이며 관측 정보에서 추정 |

임무 전체 개요는 **[05:37–07:14]**, 상세 발표는 대략 **[19:00–28:00]** 구간에 있습니다.

M1 화면에는 **탐색구간·작전거점 정보는 보고용으로만 사용하고, 해석 결과 중 지정표적만 실제 M2 임무에 사용**한다고 명시돼 있습니다. **[화면 19:00]**

M2의 지정표적 이미지는 사전 공개 자료와 실제 대회에서 동일한 형태로 사용한다고 설명합니다. M3는 6종 클래스를 인식하지만 객체 수량·위치는 비공개이고, 같은 클래스 안에서도 방향·모델·색상·배경 등이 바뀔 수 있으므로 데이터 준비와 일반화가 필요하다고 설명합니다. 한 박스의 한 면에는 한 객체를 배치하며, 박스의 여러 면에 객체가 있을 수 있습니다. **[19:38–22:21]**

M6는 상대 UGV 세 대의 **위험도 1·2·3순위를 모두 맞혀야 가장 높은 점수**를 받는다고 설명합니다. 실제 판정 기준은 생존점수·잔여탄약·객체인식점수의 세 항목입니다. 참가팀에는 상대의 정답 상태나 별도 관측상황 자료를 주지 않으므로, 정찰 영상·카메라·Depth 카메라·LiDAR·이동 및 활동 관측 등을 종합해 추정해야 합니다. 발표자는 **평가는 위험도 순위로 판정한다**고 강조합니다. **[25:56–27:36]**

통신·네트워크·대시보드·보고 API 등의 상세 내용은 별도 안내 대상으로 남겨 두고, 녹화 당시 ‘이번 주 금요일’ 추가 설명을 예고합니다. 표지 일자를 기준으로 하면 **2026년 11월 6일(금)**입니다. **[27:36–28:04]**

### 화면 예제에서 별도로 확인할 부분

**[19:00 화면]의 M1 예제에는 내부 표기 불일치가 보입니다.** 자연어와 JSON 예시의 탐색구역은 CHARLIE·DELTA인데 오른쪽 설명에는 B·D 섹터로 표시됩니다. 자연어 작전거점은 통신중계소인데 JSON의 `goal_base` 값은 `SUPPLY_BASE`로 표시됩니다. 이는 화면을 대조해 발견한 사항이며, 설명자가 별도 규칙으로 확정한 내용이 아닙니다. 실제 제출용 열거값과 예시는 후속 공식 API·자료에서 확인해야 합니다.

## 제공 로봇과 개발 도구

**[화면 30:00–32:00]** 모델은 WINGBOT-UGV이고, Jetson Orin Nano 8GB, 2D LiDAR, RGB-D/Depth 카메라, 2축 팬틸트, 레이저 발광·수광 장치를 갖춥니다. 소프트웨어 사양에는 Ubuntu 22.04, ROS 2 Humble LTS의 Docker 환경, Python·C++, JupyterLab 등이 표시됩니다.

정찰 드론은 실제 비행하는 기체 대신 경기장 중앙 상단 약 2.5m 높이의 IP 카메라와 더미 드론으로 구현한다고 설명합니다. 요청에 따라 기본 **1초당 1프레임**을 받으며, 지정표적 유효타격 결과에 따라 상대의 영상 제공이 **2초당 1프레임 → 5초당 1프레임 → 중단**으로 단계적으로 제한됩니다. **[33:11–34:17]**

경기장은 약 **6m × 5m**이고, 연습장과 본선장의 기본 구조는 같습니다. 테스트장은 두 세트를 예고합니다. 섹터 안의 박스 배치는 바뀔 수 있지만 박스 사이·벽체 사이에 **최소 40cm 간격**을 확보한다고 설명합니다. 이벤트 장치와 외부 디자인은 연습장·본선장 사이에 차이가 날 수 있습니다. 테스트용 대시보드와 본선 대시보드는 구분합니다. **[28:12–28:57, 34:17–37:13]**

서브게임은 대진 선택 우선권과 장치 검증을 위해 준비기간 둘째 날 정도에 진행할 예정이며, 본선 경기장 사전 테스트 기회도 예고합니다. 세부 운영은 오리엔테이션에서 안내할 예정이라고 설명합니다. **[37:13–38:23]**
